# TaskPulse — AI productivity verification and rewards

TaskPulse verifies that a user completed a task before awarding rewards. The backend combines **Google Gemini** (quiz generation and grading), **sentence-transformer cosine similarity** (alignment between the task summary and answers), and an **XGBoost** model (behavioral fraud features).

## Prerequisites

- Python **3.11+** (3.13 works with the pinned stack; prefer 3.11 in Docker)
- **MongoDB** (local or Docker)
- **Node.js 18+** for the UI
- **GEMINI_API_KEY** for full LLM quiz generation and grading (heuristic fallbacks run if the key is missing)

## Configuration

Copy `.env.example` to `.env` and set:

| Variable | Purpose |
|----------|---------|
| `MONGODB_URI` | e.g. `mongodb://localhost:27017` |
| `MONGODB_DB_NAME` | Default `taskpulse` |
| `GEMINI_API_KEY` | Google AI Studio key |
| `CORS_ORIGINS` | Comma-separated dev origins |

## Install dependencies

```bash
# Backend
python -m venv .venv
.\.venv\Scripts\activate          # Windows
# source .venv/bin/activate         # macOS/Linux
pip install -r requirements.txt

# Fraud model (writes backend/models/xgboost_model.pkl)
python scripts/train_fraud_model.py

# Frontend
cd frontend
npm install
```

## Run locally

**1. Start MongoDB** (if not already running), for example:

```bash
docker run -d -p 27017:27017 --name taskpulse-mongo mongo:7
```

**2. API**

```bash
# from repository root (with .venv active)
# Use "python -m uvicorn" on Windows if the bare "uvicorn" command is not found (PATH).
python -m uvicorn backend.app:app --reload --host 0.0.0.0 --port 8000
```

**3. Frontend**

```bash
cd frontend
npm run dev
```

Open the Vite URL (default `http://localhost:5173`). Set `VITE_API_URL=http://localhost:8000` in `frontend/.env` if needed.

## Docker Compose (API + MongoDB)

```bash
cp .env.example .env
# Add GEMINI_API_KEY to .env
docker compose up --build
```

API: `http://localhost:8000` · Health: `GET /health`

## API summary

| Method | Path | Description |
|--------|------|-------------|
| POST | `/users` | Create user; returns MongoDB `id` string |
| DELETE | `/users/{user_id}` | Delete user and related data |
| POST | `/tasks` | Submit task summary (`user_id`, `summary`) |
| GET | `/quiz/{task_id}` | Cached AI/heuristic quiz for the task |
| POST | `/quiz/submit` | Grade answers, similarity, XGBoost fraud blend, optional reward |
| GET | `/rewards/{user_id}` | Reward history |
| GET | `/history/{user_id}` | Tasks + quiz outcomes |

## How verification works

1. **Quiz** — Generated with Gemini when configured; otherwise a **summary-derived heuristic** quiz (still unique per summary).
2. **Score** — Gemini evaluates answers (0–30); if the API fails, **rule-based scoring** uses expected answers and summary overlap (no flat “always 15”).
3. **Similarity** — `all-MiniLM-L6-v2` embeddings: cosine similarity between the task summary and the user’s answers.
4. **Fraud probability** — XGBoost on `[score, time_taken, attempts, avg_user_score, tasks_completed_today, account_age_days, previous_rewards, time_of_day]` with **server-side stats** where possible, blended with **(1 − similarity)**.
5. **Reward** — Granted if `score ≥ 15` and `fraud_probability < 0.6`.

## Training data

`datasets/fraud_dataset.csv` columns must match inference order (see `scripts/train_fraud_model.py`). Regenerate the pickle after changing features or retraining.
